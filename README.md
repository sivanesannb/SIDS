# Adaptive Irrigation Intelligence

A machine-learning decision-support tool that predicts a field's irrigation need (**Low / Medium / High**) from soil, weather and crop data, then turns the prediction into a farmer-friendly recommendation (action + suggested water depth + the reasons behind it).

## The problem

Irrigation is often done on a fixed schedule or a single soil-moisture threshold. That wastes water when the soil already has enough, and stresses crops when demand is high. We predict irrigation need from many factors together (soil moisture, temperature, humidity, wind, rainfall, crop growth stage, previous irrigation, and more) and convert it into a clear action.

## How it works

```
Field data -> cleaning -> feature engineering -> Gradient Boosting model
           -> predicted need (Low / Medium / High, with probabilities)
           -> recommendation layer (crop stage + previous irrigation)
           -> action, dose in mm, and top reasons
```

**Recommendation layer** (`src/recommend.py`) maps the prediction to one of four actions: *No irrigation*, *Monitor*, *Irrigation recommended*, *High water-stress risk*. The suggested depth starts from the class dose (10 / 30 / 60 mm) and is adjusted:
- Flowering (most water-sensitive): +20%. Harvest: -50%. Sowing: -20%.
- Heavy recent irrigation (>= 80 mm) and not High need: -30%.
- Very little recent irrigation (<= 20 mm) and High need: +15%.

**Explanation:** for each prediction the app shows which inputs push the result most, by swapping each input for a typical value and measuring the change in probability (a simple what-if check, not SHAP).

## Results (full dataset, 20% unseen test split)

| Model | Accuracy | Balanced acc. | Macro-F1 | Recall (High) |
|---|---|---|---|---|
| Moisture-threshold baseline | 0.447 | 0.578 | 0.359 | 0.969 |
| Logistic Regression | 0.843 | 0.850 | 0.744 | 0.889 |
| Random Forest | 0.985 | 0.960 | 0.968 | 0.909 |
| **Gradient Boosting (selected)** | 0.982 | **0.967** | 0.959 | **0.941** |

The final model is chosen by balanced accuracy, because missing a High-stress field costs more than a wasted dose. The baseline's high High-recall is misleading: it over-predicts High, so its overall accuracy is only 44.7%.

**Water simulation** (assumed doses of 10 / 30 / 60 mm for Low / Medium / High vs. a fixed 30 mm schedule):

| Metric | Value |
|---|---|
| Water saved vs fixed schedule | **35.9%** (a perfect predictor would save 35.8%) |
| Under-irrigated fields | 1.02% |
| Over-irrigated fields | 0.79% |

## Dataset

[Kaggle Playground Series S6E4 (Predicting Irrigation Need)](https://www.kaggle.com/competitions/playground-series-s6e4): 630,000 rows, 19 features plus the target `Irrigation_Need`. The data was generated by a deep-learning model trained on the original Irrigation Prediction dataset, so it is **synthetic**. The dataset file is not included in this repository.

## Project structure

```
app.py               Streamlit web app (front end)
main.py              Trains, evaluates and saves the model (run once)
requirements.txt     Python dependencies
Data/train.csv       Kaggle training data (not in the repo)
outputs/             model.pkl, metrics tables, confusion matrices, plots, water simulation
src/
  config.py          Paths, class names, dose assumptions
  data.py            Loading and cleaning
  features.py        Feature engineering and encoding
  train.py           Models and cross-validation
  evaluate.py        Metrics, plots, importance, water simulation
  recommend.py       Recommendation rules and explanation
```

## Run it locally

```bash
pip install -r requirements.txt
pip install seaborn matplotlib     # only needed for training and plots

# 1. Put the Kaggle train.csv in Data/train.csv, then train (about 10-20 min on full data)
python main.py                      # use --sample 100000 for a fast run, --cv for cross-validation

# 2. Launch the app
streamlit run app.py
```

`python main.py --synthetic` runs the pipeline on generated data to test the code only; never report those numbers.

## Limitations and responsible use

- The data is synthetic and does not capture real field behaviour, so results are not field-validated and may not generalize to other regions or crops.
- Water-saving figures depend on assumed per-class doses (set in `src/config.py`) and the class mix (about 59% Low); they are a simulation, not a field measurement.
- Each row is a single snapshot; the model predicts current need, not future stress.
- This is decision support, not an irrigation controller. It should be combined with farmer judgment and local agronomic advice.
